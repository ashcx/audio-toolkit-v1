## Why
Sprint 26 shows only the encoding behavior the actual backend produces. MP3 stays constant bitrate. AAC adapts to content. Opus exposes CBR and VBR.

## What changed
- A capability table drives the Export card. Opus gets a full-width Encoding mode select. MP3 shows a constant-bitrate note. AAC shows an adaptive variable-bitrate note and a target bitrate. WAV, FLAC and stream copy show no bitrate or mode.
- The recipe schema carries a mode, rejects invalid combinations, and maps Opus/M4A VBR to the variable encoder mode. Legacy MP3/Opus recipes keep CBR; legacy M4A stays adaptive.
- VBR labels the bitrate as a target, not a fixed size. The completed player plays the encoded output.

## Scope
Sprint 26 only, rebased on `main` after Sprint 25 merged. No new codecs and no faster-isolation claim. This PR supersedes #31, which merged into the Sprint 25 branch instead of `main`. Real speech/music fixtures, AAC fallback and WebKit were not exercised.

## Tradeoffs
- Only Opus has a verified two-mode choice. AAC has one adaptive behavior, so it gets a note rather than a selector.
- AAC bitrate follows content at a fixed target, so it is not called CBR. Packet variance alone is not used as evidence.
- Times are single end-to-end runs, not a benchmark.

## Blast Radius
Touches the export schema, encoder settings, Export card and format checks. Existing CBR recipes keep their meaning. M4A was already content-adaptive; the wire value is normalized to `variable`, and the UI still offers no CBR option for it.
