# Architecture

The static Preact/Vite app runs under `/audio-toolkit-v1/`. `use-files.ts` owns file identities and inspection; `media.ts` identifies content rather than trusting extensions. File objects stay in the browser. A validated ordered recipe plus effective per-file trim becomes an immutable snapshot; `planner.ts` chooses packet copy or PCM processing, explains unsupported operations, and generates safe unique output names.

`Batch` owns attempts, scheduling, completed output files, object URLs and cleanup retry. Ordinary parallelism is one, or at most two when the capability policy permits; isolation has an exclusive slot. Cancellation stops dispatch and waits for cleanup before reusing a slot. Failed inputs do not destroy successful results. Every Export freezes and processes the requested current specs. Stored outputs retain their original settings and can be marked as previous settings when the recipe changes. Presets, test-purpose state and reuse eligibility were removed with the compact workspace.

`copy-audio.ts` preserves a matching single-track source where possible and otherwise remuxes packets. PCM work runs in a module worker. Blocks and streamed output avoid whole-recording PCM arrays. Ordered processors may create OPFS checkpoints for replay, including peak normalization; terminal encoding runs once. Unsupported decode/encode combinations fail explicitly rather than silently changing recipes.

Isolation runs HTDemucs v4 (`public/vendor/neural/htdemucs_fp16.onnx`, hash-checked when fetched and at build). `isolate.ts` spools the selection once to measure the mono mean and deviation, then streams standardized 44.1 kHz audio through `pcm/demucs-window.ts`. That file reproduces Demucs `apply_model`: 7.8 s windows (343,980 samples) every 5.85 s (25% overlap), a short final window centered over earlier audio with zeros past the end, and Demucs's triangular weights. It holds a Float32 history of STRIDE + SEGMENT = 601,965 frames per channel (13.65 s) plus Float64 accumulators and weights of 343,980 frames, so memory does not grow with track length. Each window crosses to one `inference/worker.ts` per job, which keeps one ORT session, runs the STFT, model and iSTFT in `inference/demucs-segment.ts`, and returns all four stems (drums, bass, other, vocals). Keep voice emits the vocals stem. Keep music emits drums + bass + other, summed in Float64 on the same window timeline. Output is restored by the deviation. Keep music also adds the mean once and Keep voice adds none, so voice plus music carries the source's DC offset once. Upstream Demucs adds the mean to every stem, which would triple it in a three-stem sum.

`inference/runner.ts` asks for WebGPU only when `inference/gpu.ts` finds a hardware adapter (not missing, not a fallback adapter, not SwiftShader). The GPU badge appears only after a window reports GPU compute dispatches; a WebGPU session that ran on CPU is reported as CPU. A GPU session or run failure, or a stall, retries that window on single-thread WASM and stays on WASM for the rest of the job. WASM is slower than real time (about 81 s per 60 s of audio on an Apple M5). Model download, session creation and each window have deadlines; a slow download stays alive while bytes arrive. Cancellation terminates the worker. This does not establish GPU behavior or thermals on other machines.

SCNet was the isolation model until Sprint 27, which removed it. Demucs separated 3.7 to 4 times faster on WebGPU in the Sprint 27 benchmark, and keeping two engines doubled the model, license and test surface for a slower result. The SCNet evidence stays in `docs/sprint-evidence/` as a historical record.

`output-store.ts` writes browser-backed temporary files. `cleanupAll` retains failed release callbacks. `Archive` separately owns one ZIP and URL; it reads only completed Batch outputs, locks source changes during creation, streams 1 MiB slices with CRC32 into stored ZIP64 entries, and invalidates its result when completed source URLs change. A ZIP failure leaves individual results intact. No ZIP recompression is introduced; directory saving remains optional.

Tabs do not share job state. There is no remote server, upload endpoint, persisted recipe/session database or crash-resume mechanism. A forced browser/process termination can bypass asynchronous cleanup; see privacy and acceptance records. See tests and browser drivers for executable lifecycle evidence.

`FolderSave` owns one choosing/saving/result session and AbortController. The UI detects a secure-context directory picker and invokes it from the Save action. While busy, export/result mutations and ZIP creation are locked. Folder copying receives immutable completed File objects, validates safe unique names, creates a fresh UUID batch directory and checks each destination before creation. Writes use1MiB chunks and commit on close; cancellation/error aborts the current write and removes its created partial file, reporting cleanup failure. Originals/URLs stay with Batch. Existing successful saves are never removed. The filesystem API lacks atomic exclusive file creation, so an adversarial external writer racing the new private batch path is outside the collision guarantee.

`useLevels` starts source-level measurement only while Gain or Normalize is expanded and export is idle. A cancellable worker reuses bounded `decodePcm`, accumulating peak, sample energy and sample count without whole-recording PCM retention or output checkpoints. Successful immutable File measurements are cached in a WeakMap for this tab. File changes, closing the step and export abort the current worker; stale results cannot update the new source. Readouts are complete original audio, with sample-weighted RMS across selected readable files, not processed-recipe output or LUFS. Silence is distinct from unavailable analysis.

Trim source seconds stay in RecipeDraft. `formatClock`/`parseClock` present m:ss/h:mm:ss with optional fractions; `trimHandles` creates a bounded adjustable preview for invalid per-file drafts, and `changeTrimHandle` preserves omitted/longer bounds while repairing invalid endpoints. Two native inputs share one rendered track. Secondary recipe/save actions use native disclosures with keyboard/outside dismissal. After Clear results, pending focus waits for cleanup and targets the enabled ZIP/batch recovery action, Export, or an invalid-step/file-picker fallback.
