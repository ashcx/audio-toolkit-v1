# Music isolation measurement protocol

The baseline is the pinned current SCNet implementation, including eleven-second windows, half-window overlap, a fresh inference worker per window, one terminal WAV encoder, exclusive scheduling and sticky CPU fallback. Application source is unchanged from Sprint14's reviewed technical candidate; Sprint15 changes only assessment tools/docs. Freeze a dedicated production build before measurement so later product builds cannot replace active worker assets. The model is13184191bytes, SHA-2563f049a0e4ce3c08264a6212a50445ba77f02a517cd4c6dc86cbe1ca130176d67.

Fixtures are full-length attributed instrumental music and a live congregational vocal recording, identities/license records in fixtures.json. Neither has clean separated stems. Run one actual model workload at a time, both keep modes, with complete source/output duration, sample rate/channels, frame counts, loads, window sizes and observed backend. Keep selected media local. No subjective listening is inferred from waveform existence.

This initial baseline's timer begins immediately before processAudio and ends after output inspection. It includes decode, model loading, processing, encoding, saving and output inspection, but excludes fixture HTTP fetch and initial source inspection. It is therefore a processing-plus-inspection diagnostic, not complete first-interaction latency. Fresh workers also occur within a warm browser. Both warm/cold asset caching and session reloads must be separated before a comparative speed claim. The harness records all emitted phase/backend/progress events with relative timestamps.

Only accept an improvement after five alternating complete end-to-end runs per variant, no failed/no-op outputs, matched exact grids, objective matched-reference quality, both vocal/instrumental results, cancellation/fallback/cleanup, measured peak memory and a profiler-derived limiter. A20percent median processing improvement must exceed run-to-run spread; peak memory cannot regress beyond documented headroom. These are prospective thresholds, not achieved numbers. No native/Python published speed is compared to browser results.

Current Mac is arm64,10logical cores and16GiB RAM; Chrome155 reports an Apple Metal3 WebGPU adapter. Initial load averages were3.96/2.86/2.54. No other agent benchmark is run concurrently, although unrelated system/user activity is not controlled. Device model/thermal state and process peak memory are unmeasured. Do not infer all-GPU placement from a successful mixed WebGPU/WASM session.

Reproduce using scripts/isolation-baseline-check.html as a separate Vite build entry, same worker/base config as the app, and the fixture files under fixtures/instrumental.ogg and fixtures/live.ogg. A normal preview must preserve /audio-toolkit-v1/. The isolated output lives locally under .artifacts/s16-root. No new backend configuration or optimization is part of this baseline.

Exact preparation from the repository root with supported Node22.23.1 and locked dependencies is `node scripts/prepare-isolation-baseline.mjs`. It verifies both fixture hashes, copies the committed harness to the build entry .artifacts/music16-check.html, writes the temporary Vite configuration that extends vite.config.js with this single entry and a dedicated output directory, builds all actual application worker dependencies, and copies the verified Ogg files to the frozen build's fixtures directory. Then run `python3 -m http.server 4196 --bind 127.0.0.1 --directory .artifacts/s16-root` and open http://127.0.0.1:4196/audio-toolkit-v1/.artifacts/music16-check.html . Select Run baseline music isolation once. Read the completed JSON from the visible result region and preserve failures as well as successes. Do not rerun the preparation command while this build is in use.

The harness's passed status means processing completed and output duration/rate/channel checks passed. It does not validate quality, stem accuracy, non-silence, subjective tails or absence of a legitimate identity output. Actual window/load statistics distinguish completed model calls from a capability-only check, but are not independent neural-output quality measurements. The direct processAudio harness bypasses Batch; its own cases are sequential, and it does not reverify scheduler exclusion. Batch exclusion remains a separate source/unit-tested contract from earlier sprints.
