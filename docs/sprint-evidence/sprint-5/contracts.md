# Sprint 5 frozen contracts

Compile immutable effective recipe plus matching source metadata to copy, PCM, or failed. Only proven no-ops disappear: full-source trim, zero gain, unchanged/matching channels and unchanged/matching rate. Normalization/isolation never disappear. Ordered retained steps remain ordered. Original audio with any signal-changing step fails explicitly; another format must be chosen. No silently encoded original result.

Copy uses primary-track encoded packet iteration and an encoded packet source, never sample sinks or encoder registrations. Supported targets: AAC/M4A, MP3/MP3, Opus and Vorbis/OGG, FLAC/FLAC, compatible little-endian PCM/WAV. Unsupported codec/container fails. Output carries no video. Source timestamps shift to zero while negative codec preroll remains negative; codec configuration and packet payloads must remain equivalent in actual tests.

Writes use bounded StreamTarget chunks with awaited OPFS positioned writes, never whole-file BufferTarget. M4A uses fragments to avoid retaining whole-file media/metadata. An owned output token exposes File and cleanup; only its own temporary entry is removed. Failed/cancelled attempts close/abort writers and remove partial entries. No origin-wide deletion. Actual large-file resource limits and user retry/retention are later sprint gates, not inferred from short fixtures.


Compatible single-track, zero-offset audio files retain their complete original container by bounded file slices. This preserves gapless metadata, including MP3 delay/padding. Otherwise the primary audio packets are remuxed. AAC ADTS transport headers become M4A AudioSpecificConfig; coded access-unit bytes remain unchanged. Vorbis comment vendor and FLAC checksum metadata may be regenerated by the muxer; decoding configuration means actual codec parameters, not byte-identical non-decoding comments/checksums. Independent decoded PCM comparison is required in addition to packet equality.

Mediabunny 1.63.0 does not expose Matroska DiscardPadding. An exact-hash/version-guarded source/ESM patch retains positive Opus tail padding in final packet duration and rejects unsupported padding. Complete transformations and licensing are retained in vendor/mediabunny-patches.json and THIRD_PARTY_LICENSES.md. npm ci reproduces the patch. Actual output tests compare all decoded float PCM against FFmpeg input decode, avoiding a misleading payload-only success.

Planner no-op elimination follows the current signal shape at each step. A stereo-to-mono-to-stereo or 48-to-44.1-to-48 kHz sequence retains both transformations; comparing every step to initial source metadata would be incorrect. Isolation conservatively makes its intermediate shape unknown until its owning implementation defines it.


The laced fixture is generated from checked-in tone.opus access units, with unchanged OpusHead and one final 13.5ms block-level DiscardPadding. Golden decoded audio is tone.opus (96000frames). FFmpeg6.1.1 incorrectly applies that BlockGroup padding to both laced frames and decodes95352frames; its Matroska reader passes discard_padding to every lace (n6.1.1 libavformat/matroskadec.c, matroska_parse_block loop). Therefore the reference for this one fixture is the independently decoded original Opus source, not the buggy laced demux. The browser output decodes exactly to that golden source. Other13 fixtures compare FFmpeg source/output directly. No mismatch is hidden by a numerical tolerance.

Primary format references: [Matroska DiscardPadding element](https://www.matroska.org/technical/elements.html) specifies padding at the end of the Block; [lacing notes](https://www.matroska.org/technical/notes.html) define multiple frames per Block. [FFmpeg6.1.1 source](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n6.1.1/libavformat/matroskadec.c) confirms the reference implementation limitation. Fixture generator scripts/generate-laced-fixture.mjs and method-level fixed/Xiph/EBML tests retain the verification lever.


## Processor capability freeze

This table freezes processor policy for planner consumers. Active means a step that survives no-op elimination. An inactive step may stay on the encoded copy path. Streaming and cost below describe the required implementation model and qualitative work, not a measured performance claim or proof that future processors are implemented.

| Processor | PCM requirement | Encoded-packet support | Streaming support contract | Signal change | Computational cost | Implementation evidence |
| --- | --- | --- | --- | --- | --- | --- |
| Trim | Required for any non-full-source range | Full-source no-op only; no packet-aligned precision substitution | Single pass with source-time mapping at actual card position | Selected frames/duration | Low: scan/drop/copy selected frames | Planner verified; DSP Sprint6 NOT VERIFIED |
| Gain | Required for nonzero gain | Zero-gain no-op only | Single pass, bounded block | Multiplies amplitude, may clip | Low: one multiply per sample | Planner verified; DSP Sprint6 NOT VERIFIED |
