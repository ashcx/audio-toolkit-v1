# S06-US03 processing topology and presentation

The actual browser harness observes worker completion messages without product debug controls. Each exported PCM job must report one input decode, one terminal encoder, exact encoded frames and maximum block size ≤4096. Every normalization card adds one checkpoint analysis/replay at that card's position. All reported frame counts are checked against independently decoded downloaded WAVs.

Fresh per-case probes isolated native WebKit FLAC errors and Vorbis stalls. Lazy bounded WASM decoders resolve these codecs without whole-file decode. Separate probes established negative AAC timestamp distortion and inconsistent native Opus pre-skip. Pinned source/ESM patches correct those boundaries; MP3 gapless parsing and fractional Matroska delay preserve presentation. Corrected-presentation-probe/results.json records all six audio families at 96000 frames in both engines, with independent decoded-head errors. Raw ADTS/offset-container exceptions are explicitly frozen in contracts.md and tested separately rather than normalized to a convenient expected count.

Inherited workspace/intake/recipe/copy suites pass with current Sprint 6 artifacts in separate regression folders. Copy still constructs no decoders/encoders and preserves independently decoded PCM hashes. Actual processing checks include storage quota failure, successful retry, removing an active write, output removal and checkpoint cleanup. No external requests or model loads are needed for DSP. Physical-device support and final memory limits remain unverified.
