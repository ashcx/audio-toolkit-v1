# S08-US03 prove terminal cleanup

The existing PCM runner remains the owner of its worker and temporary stores until success. Batch owns only the final returned output. Abort terminates the worker before awaiting outstanding storage RPCs and discarding temporary stores. Copy abort disposes its input and observes the signal between bounded writes/packets, then discards incomplete output. New phase events do not alter sample or packet data.

The browser driver injects invalid input, nonfinite processing, invalid encoder configuration, write failure and close failure into actual production execution. Each failure is isolated, other files finish, Retry failed succeeds, and OPFS contains exactly retained completed results. Tests hold real OPFS writes/close pending while cancelling; no download appears for a cancelled attempt. Active PCM-worker count returns to zero after idle. Unit tests cover owner disposal and ignored stale completions. Actual page/process termination cannot guarantee asynchronous cleanup and is not claimed as a browser background feature.

27 unit tests, current build/source/worker-import guards and browser batch/copy checks pass. Mixed MP3 and inherited DSP/format regressions validate downloaded audio rather than compilation alone. Workspace, intake, recipe and96-download format regressions pass. DSP58 and final independent integrated review passed; see coverage.md and interrogate.md. Initial driver failures were instrumentation issues: default child-process buffer size, selecting the idle Export label during active work and assuming FFmpeg mono-to-stereo amplitude. The driver now reads bounded fixture bytes, selects the active button directly and compares measured input/output peak ratios. No product bug was hidden by those changes.
