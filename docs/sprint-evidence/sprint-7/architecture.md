## Existing flow

Main snapshots each file's ordered recipe and detected source. Planner picks copy, PCM or failure. Copy preserves compressed audio. PCM worker consumes one decoder through ordered generators, writes checkpoints through the main-owned storage bridge, clamps only at terminal encoding and closes/finalizes its single source/output. It currently permits only WAV and hardcodes WAV names. Main retains completed File and URL, marks stale settings and releases output on removal. Extending export must preserve those owners.

## Design exploration and synthesis

Terra low proposed shared pure descriptor plus worker configuration/preparation functions. Luna low proposed terminal encoder adapter owning append/finalize/cancel and AudioSample creation. Both require exact first-block shape before codec capability checks and no implicit sample-rate changes. Select Terra as base: all five formats already use the same Mediabunny source/output lifecycle, so another lifecycle owner would duplicate that abstraction. Graft Luna's explicit finalization/cancellation checks into acceptance; keep existing worker as sole owner. No judge, no implementation delegates. Existing code signatures are retained apart from adding format helpers and encoder telemetry.

Caller sketch: main uses `exportDescriptor(recipe.export).extension` for PCM filenames. Worker derives descriptor/config/container from the same validated recipe export, and `prepareEncoder(export, actualFirstBlockShape)` before starting output. Returned backend is native/wasm/pcm for observed test assertions, not a user-facing implementation badge. Bounded PCM source/checkpoint interfaces do not change. Terminal state remains output start, awaited sample adds, close source, awaited finalize, close store; cancel on failure.

Pure `export-format.ts` owns descriptor and statically known invalid-rate rules without importing the heavy media library into main. Worker `pcm/encode.ts` owns library config/container construction and lazy codec registration, not storage or PCM iteration. MP3 uses pinned LAME WASM; FLAC uses pinned libFLAC WASM with 24-bit output from f32 PCM. AAC prefers verified native exact rate/channel/bitrate capability, otherwise lazily registers the rebuilt pinned-source fallback and rechecks. Registration clears the library capability cache. Native Opus uses OGG; unsupported native capability fails clearly. Current Chromium/WebKit native Opus feasibility exists; physical/browser minimums remain final-device gates, no new Opus fallback is claimed.

## Frozen output contract

MP3 audio/mpeg/.mp3 at128/192/256/320kbps. AAC-LC audio/mp4/.m4a at128/192/256kbps, nonfragmented seekable MP4 with fastStart false to avoid in-memory media buffering. WAV audio/wav/.wav PCM16, existing4GB guard. FLAC audio/flac/.flac24-bit, lossless relative to its documented quantized terminal samples. Opus audio/ogg/.ogg at64/96/128/160/192kbps. Exact output codec/channel/rate/headers and finite decode must be inspected independently. All offered rates are tested where legal. Native Opus accepts8/12/16/24/48kHz; 44.1/32kHz require an explicit recipe resample to a legal rate, with clear per-file error and recovery. No hidden resampling/downmixing. Other codec invalid shape/capability rejects before encoding samples.

Lossless duration within one frame; PCM16 error ≤1/32768, FLAC24 error ≤1/8388608 plus input rounding. Lossy output tests must independently account for encoder priming/padding and verify final-tail signal presence, not merely container duration. Exact observed lossy presentation/gapless policy will be frozen from short/tail probes before acceptance. No silent trimming/padding to fit convenient expected counts. Long outputs must flush and remain decodable; full RSS limits remain Sprint11.

The initial freeze inherited an open AAC exact-source audit. The implementation resolves that specific gap through the pinned-source rebuild documented below; codec feasibility and user hosting alone did not resolve it. Preserve all notices and separate native suitability from fallback execution. No claim of physical-device or universal native codec support. All format UI uses existing minimal Format/Bitrate controls.

## Experimental corrections during implementation

Initial production WebKit MP3/FLAC/Opus jobs stalled while isolated dev-worker encoding succeeded in both engines. Generated encoder chunks imported the PCM worker entry, creating a cycle. A dedicated worker-media chunk removes the entry back-import. Fresh production probes then completed all five formats in both engines. scripts/check-worker-imports.mjs is in the build and was proven to fail on the actually regenerated prior bundle shape.

Native WebKit AAC with 2048-frame input emitted duplicated packet timestamps; 1024-frame submissions removed duplication. Its priming probe still produced a false positive start and distorted waveform. A nonnegative priming-probe experiment aligned the head but independent decode exposed lost tail samples (93632 vs96000). Do not keep that source patch. This measured native path is unsuitable, so WebKit uses the pinned AAC fallback, while other engines still prefer native when capable. Both current automated engines use fallback; successful native AAC on other actual platforms remains NOT VERIFIED. This is a suitability correction, not a claim of universal native failure.

MP3 output needs a finalized LAME gapless tag and an audio-frame count excluding the muxer metadata frame. A bounded final Xing-frame rewrite expresses actual LAME576-sample encoder delay and measured terminal padding; independent FFmpeg decode changed97920→96000 frames, and source presentation metadata now reads the same96000. Xing offsets follow the primary FFmpeg parser and do not add CRC length.

Native Opus flush omitted its lookahead tail in WebKit and added packet padding in Chromium. Submit one silent20ms encoder flush quantum, then retain at most four bounded OGG pages, select the page containing the real end, retain encoded packets through that end, set final granule/EOS and recompute CRC. Awaited positioned write plus owned-store truncate removes padded pages; no audible padding is included. Merely rewriting the last page failed for a non-frame-aligned48037-frame fixture because an earlier page had passed the target. The corrected tail rewrite independently decodes exactly48037. Input-rate rounding occurs before Opus’s mandatory48kHz decode clock. This extends the storage protocol with one typed truncate operation; all ownership/cleanup contracts stay intact.

AAC decoded length may include up to1023 trailing packet-padding samples, with zero presentation start and complete source head/tail. MP3/Opus decoded effective length is exact; MP3 container duration can include its tagged decoder delay. FLAC24 and WAV16 remain exact. Low-rate MP3/AAC bitrate limits are rejected before the encoder can silently cap them. These refinements freeze observed codec contracts before final acceptance.
