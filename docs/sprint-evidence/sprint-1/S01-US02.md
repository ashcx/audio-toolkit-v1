# S01-US02 browser and static-path feasibility

Synthetic smoke harness is `probes/index.html`, `probes/probe.js`, `public/probes/isolation-worker.js` and `scripts/browser-probe.mjs`. Run `npm run build`, start `npm run preview -- --port 4173`, then `PROBE_URL=http://127.0.0.1:4173/audio-toolkit-v1/probes/ npm run probe`.

Actual JSON results and exact combined output are retained in this directory. This production build exercises a nested Pages-style base path without cross-origin isolation. The SCNet worker uses relative runtime/model paths and a single WASM thread. No header/service-worker workaround is required for the demonstrated single-thread path. Live GitHub Pages and real devices are not tested or deployed.

First Chromium run produced valid playable/decodeable MP3, M4A/AAC, WAV, FLAC and Opus-in-OGG output and compatible AAC copy. The initial WebKit FLAC decode failed with EncodingError despite advertised native support. A bounded compressed-input FLAC decoder probe using 4096-byte chunks recovered the expected 44100 samples. Exact fallback use is captured in the WebKit JSON. This proves a feasible codec fallback, not production fallback integration or large-file safety.

Single-thread Chromium isolation verified the pinned model digest, expected voice/music frame counts and finite samples. This is a synthetic smoke test only. It does not prove musical quality, overlap boundaries, bounded song memory or long-recording feasibility. The upstream whole-song API must be adapted before Sprint 9 acceptance.

Initial setup failures were missing Playwright browser executables and WebKit shared libraries. Installed dev/test browser runtimes and their dependencies, then reran. A Vite import of a public worker initially produced HTTP 500; serving that worker as a static asset fixed it and allowed actual inference. These were harness/setup failures, not passing product checks.

The production-path rerun also passed single-thread isolation on Linux WebKit. JSON files `chromium-isolation-probe.json` and `webkit-isolation-probe.json` each record the expected digest, 44100 voice/music frames and finite samples.

Bounded synthetic feasibility was then tested with `node scripts/resource-probe.mjs`. It generates five sequential independent one-second inference tasks, awaiting and terminating each worker before the next. No song-length PCM or separated outputs are retained in the host. Inputs are capped at 44100 frames per job; only frame-count/hash result summaries return. Five jobs processed 220500 frames with zero errors. The script samples all Chromium processes' RSS through CDP process IDs and `/proc`, with a predeclared 2 GiB aggregate RSS budget. Observed peak was 1759260672 bytes across 266 samples. Load before the run was 0.06/0.31/0.26 on four cores. This is a single bounded-cap feasibility observation, not a throughput benchmark, supported mobile memory limit, duration-scaled production proof or quality comparison. The model uses fixed 485100-sample/476-frame internal segments, explaining why a small input still has substantial inference memory. Production streaming overlap/output retention remain Sprint 9/11 gates.
