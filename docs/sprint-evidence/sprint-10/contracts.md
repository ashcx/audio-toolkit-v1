# Sprint 10 contracts

Single Batch owns tests and regular exports. A job carries test or batch purpose. Batch export consumes a matching completed test once, retaining the same output URL and cleanup owner. Matching requires stable File identity and the complete effective plan including trim override. Input/settings edits invalidate eligibility immediately; reverting settings does not revive it. A retry retains its original purpose and frozen snapshot.

First file is the test default; a selector permits any chosen file. Test and export share the same runner, worker concurrency, isolation exclusivity, cancellation, error and cleanup behavior. Previous results remain downloadable when settings change, but cannot be silently reused.

Presets are editable recipes. MP3, speech, voice and karaoke preserve the existing trim step and stable-ID overrides. Original extraction clears incompatible trim only after confirmation when ranges would be lost. Peak normalization is labeled as peaks and targets -1 dBFS.

Throughput checkpoint. Blocking first steps are predecessor verification and identity/lifetime freeze. Independent workstreams are n/a because Scrum requires sequential main-instance implementation. Shared mutable state is the Batch job and output owner; no second preview cache is introduced. Smallest safe decomposition is one story at a time with unit and browser evidence before the next sprint.

Design exploration compared a second preview cache with ownership transfer against a single Batch owner with test intent. The latter avoids a second cleanup lifecycle. Terra low supplied an independent sketch; the second panel could not start because the runtime reached its agent-thread limit. Main compared alternatives sequentially. Independent sprint review remains required.
